# Gastroesophageal Reflux (GERD) Classification from Oesophageal pH Recordings

Supervised learning assignment: binary classification of **acid reflux (1)** vs. **non-acid reflux (0)**
from oesophageal pH sensor time-series, comparing **Neural Networks (Keras/TensorFlow)**,
**Support Vector Machines** and **k-Nearest Neighbours** (scikit-learn).

All experiments are reproducible on a standard Linux machine (Ubuntu 20.04+).

├── code/             # all Python scripts

## Requirements

- **OS**: standard Linux (targets Ubuntu 20.04+; no Windows-specific paths are used and no
  Linux-only API is required).
- **Python**: 3.12 recommended (TensorFlow 2.19 supports Python 3.9–3.12; there are no 3.13+ wheels).
- **Packages**: pinned versions in `requirements.txt` — numpy, pandas, matplotlib, seaborn, scikit-learn, scipy, tensorflow, setuptools. The scripts in `code/` import numpy, pandas, matplotlib, seaborn, scikit-learn and tensorflow directly; scipy and setuptools are kept pinned because scikit-learn and TensorFlow/Keras respectively require them at run time (see the note in `requirements.txt`).

## Running the Experiments

All scripts use relative paths and read their data from `data/` (falling back to the
project root for datasets that have not been moved yet) — **run them from the project root**:

```bash
# 1. Data preparation (fast, < 1 min)
#    Parses the raw recordings in data/, engineers windowed features for window
#    sizes 30/60/120, and writes data/features_30.csv, data/features_60.csv and
#    data/features_120.csv.
python code/phase1.py

# 2. Algorithm experimentation — independent of each other, but they require the
#    data/features_*.csv files written by step 1 (they also fall back to the stale
#    project-root duplicates if data/ is empty).
python code/phase2_nn.py     # NN-1..NN-4 5-fold CV, Adam vs. SGD, window sizes + learning curves (~30–60 min)
python code/phase2_svm.py    # linear/polynomial kernels, RBF C/gamma grid + heatmap, window sizes (~2–5 min)
python code/phase2_knn.py    # k/metric/weighting grid + accuracy-vs-k plot, window sizes (< 1 min)

# 3. Final evaluation (a few minutes)
#    Trains the final NN (NN-4, Adam), SVM (RBF, C=100, gamma=0.01) and k-NN
#    (k=25, Manhattan, distance weighting) on the full training set and evaluates
#    them once on the held-out test set.
python code/phase3.py
```

### Notes

- Re-running `code/phase1.py` regenerates `data/features_30.csv`, `data/features_60.csv` and
  `data/features_120.csv` from the raw recordings in `data/`. The three `features_*.csv` files
  in the project root are the stale pre-migration duplicates described above and are not
  rewritten; `code/phase1.py` always prefers `data/` and only falls back to the project root
  when a file is missing from `data/`.
- `code/phase1.py` runs the missing/anomalous-value check the brief asks for
  (`e.g., pH < 0 or pH > 14`): it counts readings with `pH < 0` and readings with
  `pH > 14`, prints the total and the anomaly percentage, and lists the offending rows when
  there are any. Every pH value in the two raw recordings in fact lies inside `0–14`, so the
  script reports `Total anomalous: 0` and prints
  `No anomalous readings found: every pH value lies within 0-14.` — a clean dataset (the
  pH range itself is still printed just above the check).
- Every figure is written to `outputs/` as a PNG by a `save_fig(filename, dpi=150)` helper
  (`plt.savefig(..., bbox_inches='tight')`) and only then displayed with `plt.show()`, so the
  scripts print `saved figure: outputs/<name>.png` for each plot. Filenames are descriptive,
  `phase`-prefixed and unique per script (`phase1_…`, `phase2_nn…`, `phase2_svm_…`,
  `phase2_knn_…`, `phase3_…`), so re-running a script overwrites exactly its own figures and
  never another script's. On a headless server, either
  run from a desktop session / with X11 forwarding, or set `MPLBACKEND=Agg` — figures are then
  still saved to `outputs/` but not displayed, and `plt.show()` prints
  `FigureCanvasAgg is non-interactive` warnings (expected, harmless), e.g.:

  ```bash
  MPLBACKEND=Agg python code/phase3.py
  ```

- `code/phase3.py` opens several figure windows (3 confusion matrices, 1 ROC plot,
  1 precision-recall plot); close each window to continue when using an interactive backend.
- `outputs/` is the designated location for the figures/plots produced by the
  experiments; each script creates the directory itself (`os.makedirs('outputs', exist_ok=True)`)
  and writes one PNG per figure, so a fresh checkout needs no manual setup.

## Reproducibility

- All random seeds are fixed to `42` (Python `random`, NumPy, TensorFlow), and the
  train/test split is stratified with `random_state=42` in every script.
- `code/phase1.py` is deterministic; the committed CSVs match regenerated output up to
  last-bit floating-point rounding in the `slope` feature (differences between NumPy builds).
- The reference numbers in the next section come from a CPU run with the pinned versions
  above; they have not been re-derived on every platform.
- The RBF grid numbers in the next section were recorded before the search was refactored to
  `GridSearchCV`. The refactored search uses the identical estimator, grid, scoring and folds
  (`GridSearchCV` clones the `StratifiedKFold` splitter per candidate, so every candidate is
  scored on the same folds), so it is expected to reproduce those per-cell accuracies exactly.
- Cross-validation is 5-fold `StratifiedKFold(shuffle=True, random_state=42)` on the
  training set only; the test set is used once in `code/phase3.py`.
- The learning-curve means in `code/phase2_nn.py` are accompanied by the **population**
  standard deviation (`np.std(..., ddof=0)`), whereas the window-size comparisons in
  `code/phase2_svm.py` and `code/phase2_knn.py` call `.std()` on the `cross_val_score`
  array, i.e. the **sample** standard deviation (`ddof=1`). For 5 folds the two conventions
  differ by a factor of `sqrt(5/4) ≈ 1.118`, so a `phase2_nn.py` SD is about 10.6% smaller
  than the same spread reported by the other two scripts — compare means across scripts, not
  SDs.
- The RBF SVM hyperparameters are tuned with
  `GridSearchCV(SVC(kernel='rbf'), param_grid={'C': [0.1, 1, 10, 100], 'gamma': [0.001, 0.01, 0.1, 1]},
  scoring='accuracy', cv=StratifiedKFold(n_splits=5, shuffle=True, random_state=42))`, i.e. 16 candidates ×
  5 folds = 80 fits on the window-30 training set. The heatmap is drawn from
  `cv_results_['mean_test_score']`, and the window-size comparison reuses the
  `best_params_` (`C=100, gamma=0.01`) that the search selects, so tuning and the
  downstream experiments cannot drift apart.
- The final network in `code/phase3.py` follows the brief's epoch rule
  (`use early stopping on validation loss`): it is trained with
  `validation_split=0.1` and
  `keras.callbacks.EarlyStopping(monitor='val_loss', patience=10, restore_best_weights=True)`
  for at most `epochs=100`, exactly like the NN experiments in `code/phase2_nn.py` (which use
  an explicit validation fold from the 5-fold CV instead). The 10% validation split comes out
  of the training set, so the held-out test set is still only used for the final
  `evaluate`/`score` calls. Because the early-stopped network is no longer the same network as
  a fixed 100-epoch fit, the `Final Neural Network` accuracy/loss in the reference block below
  (recorded before this change) can move by roughly ±0.01.
- All three final models in `code/phase3.py` are timed with `time.perf_counter()` around their
  `fit` calls, and the script prints a `Training Time Comparison` block (SVM / k-NN / neural
  network, seconds) plus a per-model `Training time` line, which is what the report's
  "training time of SVM compared to NN and k-NN" question is answered from. The times are
  wall-clock and therefore machine-dependent; only the ordering (k-NN ≈ instant,
  network seconds, SVM slowest) is stable.

## Troubleshooting

- `ModuleNotFoundError` for `numpy`/`pandas`/`matplotlib`/`seaborn`/`sklearn`/`tensorflow`
  — the virtual environment is not active, or `pip install -r requirements.txt` was not run.
  (No script imports `setuptools` or `scipy` by name; both are pinned in `requirements.txt`
  only because TensorFlow/Keras and scikit-learn require them at run time.)
- `pip` cannot find a matching TensorFlow wheel — your Python is newer than 3.12;
  use Python 3.9–3.12.
- Tkinter/display errors when plotting — set `MPLBACKEND=Agg` (see Notes above).
